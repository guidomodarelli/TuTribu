Una biblioteca compartida

beez-ui concentra los componentes y las modificaciones reutilizables entre repositorios.

Actualizado: 2026-09-07 · pnpm 12.3.4

Responsabilidades

El repositorio beez-ui es la fuente de verdad para los componentes originales de LaTribu y los componentes reutilizables de agenda-mensual. Incluye sus modificaciones, utilidades de clases, detección móvil, contrato de cookies del sidebar, props para integrar la navegación del consumidor y acceso a Sonner.

El tema default, los tokens y las fuentes locales de LaTribu pertenecen a beez-ui. TuTribu conserva sus componentes de producto, SCSS Modules y preferencias de página. No contiene copias de los componentes compartidos. Las capas de dominio y aplicación no dependen de esta biblioteca de presentación.

Contrato de consumo

import { Button, Dialog, Input, toast } from "beez-ui";

Agrupar los imports nombrados desde la raíz. El barrel no tiene use client: cada módulo mantiene su frontera original. Next.js configura transpilePackages y experimental.optimizePackageImports para compilar el TypeScript distribuido e importar únicamente los módulos usados.

La biblioteca usa React y no depende de Next.js ni de next-themes. AvatarImage delega carga y fallback a Base UI. No se exporta un componente Link: el wrapper @/components/navigation/link vive en LaTribu, mantiene prefetch desactivado y se pasa mediante component a la paginación compartida.

Importar beez-ui/styles.css después de Tailwind en la hoja global. Esa hoja registra las fuentes del paquete mediante @source, importa las animaciones y declara el mapeo de tokens. La hoja incluye el tema claro/oscuro de LaTribu y sus fuentes como default. El consumidor puede sobrescribir tokens y mantiene los estilos de sus pantallas.

Distribución reproducible

La entrega inicial usa vendor/beez-ui-0.1.0.tgz y un lockfile con integridad. El tarball se genera desde el repositorio de la biblioteca con pnpm pack. Permite instalar y construir TuTribu en CI o en otro checkout sin acceso al directorio hermano. No requiere una publicación en un registry.

  1. Modificar los componentes en beez-ui y ejecutar pnpm check.
  2. Incrementar la versión y generar el paquete con pnpm pack --pack-destination ../LaTribu/vendor.
  3. Actualizar la dependencia y el lockfile del consumidor con pnpm add ./vendor/beez-ui-VERSION.tgz.
  4. Ejecutar tests, typecheck, lint, build y validar los flujos visuales en Chromium y WebKit.

Los nuevos componentes upstream se incorporan mediante el CLI oficial de shadcn/ui dentro de beez-ui. Revisar sus imports internos y exportarlos desde la raíz. No ejecutar ese CLI en el consumidor.

Compatibilidad y pruebas

Se preservan Button.asChild, estados deshabilitados, fallback y reintento de avatar, preferencias del sidebar e hidratación determinista. La librería usa Vitest 5.0.0 y cnfast 0.2.0, y cubre esos contratos con componentes reales; TuTribu verifica su consumo desde el artefacto instalado y sus flujos de producto.

Las pruebas del sidebar usan providers reales. Se conservan los dobles preexistentes de notificaciones para aislar los timers y el estado global de Sonner, con el resto de exports reales.

Tooling de la biblioteca

El código y los tests de beez-ui se verifican con TypeScript 7 mediante configuraciones separadas. La API de TypeScript 6 se conserva mediante el alias oficial de compatibilidad para typescript-eslint; el comando tsc sigue ejecutando TypeScript 7. Las dependencias de la biblioteca usan rangos ^ y el lockfile fija las versiones verificadas.

Revisión de constantes

El contrato de cookie se define una sola vez en beez-ui/src/constants/sidebar.ts y se exporta desde la raíz para el servidor y el cliente. Los anchos y el atajo del sidebar y el breakpoint móvil permanecen locales. El avatar ya no impone dimensiones numéricas heredadas de Next.js; su tamaño pertenece a los estilos del componente. Se preservan los nombres y valores públicos; las unidades quedan documentadas.

ESLint 10

LaTribu y beez-ui usan ESLint ^10.10.0. En LaTribu, eslint-plugin-import@2.32.0, eslint-plugin-jsx-a11y@6.10.2, eslint-plugin-react@7.37.5 y eslint-plugin-no-eslint-disable@3.0.2 mantienen rangos de peers anteriores. Se admite exclusivamente ESLint 10.10.0 para esas versiones mediante peerDependencyRules.allowedVersions, después de ejecutar el lint completo y verificar errores de imports duplicados, imágenes sin alt, elementos sin key y comentarios de desactivación. Los presets de Next mantienen fixupConfigRules. Esta validación local no modifica la compatibilidad declarada por los autores: revisar y retirar las excepciones cuando publiquen soporte, y revalidarlas antes de ampliarlas.

Integración de agenda-mensual

Se incorporan Alert, AnimatedThemeToggler, Calendar, DataTable, FilterQueryBar, Form, Highlighter, InputGroup, Label, RadioGroup, TypingAnimation y ThemedToaster, junto con sus tipos y gramática. La tabla preserva agrupación, filtros configurables y memoización. Los componentes mantienen el tema de LaTribu y sus primitivas existentes.

El tema es controlado por el consumidor: AnimatedThemeToggler recibe theme, resolvedTheme y onThemeChange; ThemedToaster recibe theme. La biblioteca no resuelve ni persiste el tema por su cuenta. El sidebar ofrece storageKey opcional sin cambiar su cookie pública ni los defaults del servidor. Los paneles largos admiten scroll y los botones exponen variante y tamaño.

Las pruebas de tabla y filtros se trasladaron a Vitest conservando sus escenarios. Se agregaron pruebas de integración de las primitivas y una app React/Vite para validar interacción, tema y responsive en Chromium y WebKit. agenda-mensual se usó como fuente de lectura; su aplicación no se modificó.
