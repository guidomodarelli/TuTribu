CONVENTION
Motion
Cómo agregar animaciones sutiles y consistentes en componentes de producto con motion y mixins SCSS, respetando prefers-reduced-motion, el render en servidor y ambos motores (Chromium y WebKit).
Scope: UI / Styling / InteractionStatus: Active
01
Overview

La animación en TuTribu comunica cambios de estado: algo entró, algo salió, algo se guardó, un valor cambió o una región se expandió. No es decoración. Los primitivos de beez-ui (diálogos, menús, popovers, tooltips, sheets, tabs, sidebar y el press de Button) ya animan con motion; esta convención cubre la animación de los componentes de producto que viven en este repositorio.

Hay dos herramientas, según dónde se renderiza el contenido:

CasoHerramientaPor qué
Entrada de contenido renderizado en el servidor (secciones, listas iniciales, estados vacíos)Mixins SCSS de src/styles/_motion.scssCorren sin JavaScript, no ocultan el HTML del servidor antes de hidratar y funcionan en Server Components.
Cambios en el cliente (ítems agregados o borrados, contadores, estados de envío, regiones que se expanden, indicadores que se deslizan)motion/react y las primitivas de movimiento de beez-uiNecesitan presencia (animar antes de desmontar), layout y dirección del cambio.
02
Rules
  • Animar solo transform y opacity (y altura únicamente a través de AnimatedCollapse). Nunca animar width, top, margin ni sombras pesadas en listas largas.
  • Duraciones de 120 a 320 ms con la curva ease-out fuerte cubic-bezier(0.16, 1, 0.3, 1). Las salidas son más cortas que las entradas para no bloquear la siguiente interacción.
  • Sin loops decorativos. Solo indicadores de carga pueden repetirse, y se detienen con reduced motion.
  • Reduced motion siempre. BeezUIProvider monta MotionConfig reducedMotion="user" para toda la app, y cada mixin SCSS se desactiva bajo prefers-reduced-motion: reduce. No agregar animaciones fuera de esos dos caminos.
  • No ocultar HTML del servidor. No usar initial={{ opacity: 0 }} de motion en contenido que llega renderizado: se ve vacío hasta que hidrata. Envolver listas cliente en <AnimatePresence initial={false}> para que solo animen los cambios posteriores.
  • No re-animar primitivos de beez-ui. Sí se pueden animar cambios internos de un diálogo (pasos, errores, listas).
  • Valores con nombre. Duraciones, curvas y resortes salen de los tokens que exporta beez-ui (MOTION_TIMING, MOTION_EASE, MOTION_EASE_IN_OUT, SPRING_LAYOUT, SPRING_POP y las distancias), los mismos que usan sus primitivas; no se copian en la aplicación.
03
Primitivas cliente
Componente (desde beez-ui)Uso
AnimatedCollapseExpande y colapsa una región animando altura y opacidad; libera overflow al terminar para no recortar anillos de foco ni popovers. El padding va dentro del contenido.
PresenceSwapCross-fade entre estados de una misma región (sin cambios → guardando → guardado). Cambiar presenceKey dispara la transición; el primer render no anima.
AnimatedCountContadores (me gusta, asistentes, no leídas): el número rueda hacia arriba al subir y hacia abajo al bajar.
AnimatedListItemÍtems de lista que entran, salen y reacomodan a sus hermanos con un resorte. Va dentro de <AnimatePresence initial={false}>.

PresenceSwap y AnimatedListItem vuelven inert y aria-hidden al elemento mientras sale: un ítem borrado o un estado reemplazado no se puede enfocar, clickear ni anunciar durante su animación. No hace falta envolver el contenido en otro componente para lograrlo.

En listas largas (más de unas decenas de filas) desactivar el reacomodo con layout={false} para no medir cientos de nodos en cada cambio.

04
Usage
// styles.module.scss — entrada CSS para contenido del servidor.
@use "../../../src/styles/motion";

@include motion.define-keyframes; // keyframes locales al módulo

.MemberList {
  &__item {
    @include motion.stagger(8);     // escalona los primeros 8 hermanos
    @include motion.interactive;    // hover/focus consistentes
  }
}

// Componente cliente — ítems que llegan después del primer render.
<ul className={styles.NotificationPanel__list}>
  <AnimatePresence initial={false}>
    {notifications.map((notification) => (
      <AnimatedListItem key={notification.id}>…</AnimatedListItem>
    ))}
  </AnimatePresence>
</ul>
CSS Modules localiza los nombres de @keyframes por módulo; por eso cada módulo que anima incluye motion.define-keyframes una vez, en el nivel superior.
05
Testing
  • En Vitest, vitest.setup.ts hace que matchMedia reporte prefers-reduced-motion: reduce: las animaciones de transformación se omiten, pero las salidas de AnimatePresence siguen siendo asíncronas. Esperarlas con waitFor o findBy*.
  • Con fake timers, falsear solo setTimeout, clearTimeout y, si hace falta, Date (vi.useFakeTimers({ toFake: ["setTimeout", "clearTimeout", "Date"] })). jsdom programa requestAnimationFrame con un setInterval: si se falsea y se restaura con un frame pendiente, las animaciones de salida quedan congeladas en todos los tests siguientes del archivo. Por lo mismo, PresenceSwap mode="wait" nunca muestra el estado nuevo bajo fake timers completos.
  • No mockear motion ni beez-ui. Los tests validan el comportamiento observable (qué queda en el DOM, foco, roles), no los valores de la animación.
  • El recorrido real de las animaciones se valida en navegador, en Chromium y WebKit, en 375 px y desktop, y también con reduced motion activado.
