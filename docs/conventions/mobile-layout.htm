CONVENTION
Mobile Layout
Reglas para que cada pantalla y componente funcione en teléfonos (360–430px, Chromium y WebKit): diálogos que scrollean, inputs sin zoom de iOS, tablas apiladas, targets táctiles y equivalentes touch para interacciones de hover.
Scope: UI / StylingStatus: Active
01
Overview

El layout de plataforma (app/(platform)/layout.module.scss) acota el contenido a 720px con padding: clamp(1rem, 3vw, 2rem) y un header sticky de 3.5rem. En un teléfono de 360px quedan ~328px útiles. Todo estilo base (sin media query) es el estilo mobile: las variantes de escritorio se agregan con @media (min-width: …), nunca al revés.

Rules

Diálogos (DialogContent)El contenido tiene max-height: calc(100svh - 2rem) y overflow-y: auto por defecto, así el footer con la acción principal siempre es alcanzable en pantallas cortas o con teclado abierto. Controles de formularioTodo input, textarea, select o contenteditable de producto renderiza a 1rem (16px) por debajo de 48rem; la versión compacta (0.875–0.95rem) va en @media (min-width: 48rem). iOS Safari hace zoom de página al enfocar texto menor a 16px. Los Input/Textarea de shadcn ya cumplen con text-base md:text-sm.lesson-comments, rich-link-editor, tribe-channel-management
Tablas de gestión y listadosPor debajo de 48rem la tabla se apila: table, thead y tbody en display: block, la fila de encabezado oculta, cada tr como grid (o flex con wrap para filas de dos líneas) y las celdas en bloque con white-space: normal. Solo la tabla de métricas de invitaciones conserva el scroll horizontal del contenedor de shadcn.tribe-subscription-price-management, tribe-events-calendar
Grilla mensual del calendarioPor debajo de 48rem la grilla ocupa el 100% (sin min-width: 42rem): celdas compactas y píldoras que muestran solo la hora; el título vive en el diálogo de detalle que abre la píldora.tribe-events-calendar
Layout elegido por viewport en clienteuseIsMobile devuelve false en el servidor. Un componente que elige entre dos layouts con ese hook debe renderizar ambos hasta hidratar (detectado con useSyncExternalStore y snapshot de servidor false) y dejar que una media query, con el mismo breakpoint de 768px, muestre el correcto. Tras hidratar queda un solo layout en el DOM.tribe-events-calendar (__autoView--calendar / __autoView--list)
Grillas con varias columnas fijasCuando la suma de columnas auto/max-content supera el ancho disponible, reorganizar con grid-template-areas en dos filas por debajo de 40rem en vez de dejar que la columna 1fr colapse a cero.__imageDraft, __fileDraft en tribe-round
Botones flotantesNo usar position: fixed abajo a la derecha en mobile: tapa controles alineados a la derecha y salta con el teclado. Usar una barra sticky de ancho completo al final del formulario con fondo y safe-area-inset-bottom.tribe-welcome-management
CarruselesLos botones prev/next de shadcn (-left-12/-right-12) solo caben en desktop. Por debajo de 64rem se superponen al slide con [data-slot="carousel-previous"]/[data-slot="carousel-next"], 2.5rem de tamaño y fondo translúcido.tribe-story-gallery
Targets táctilesAcciones primarias y de navegación con al menos 2.5rem de área tocable. En el header se aplica con @media (pointer: coarse) sin alterar el tamaño en escritorio.app/(platform)/layout.module.scss
Interacciones solo hoverUn HoverCard o Tooltip nunca abre desde touch. Cuando la información es necesaria, detectar (hover: none) con useSyncExternalStore y ofrecer un Popover con trigger propio (el tap original conserva su acción).message-likes-hover-card
Padding de páginaUn módulo de página no debe redefinir el padding completo del main: si necesita ajustar el bloque, usar padding-block y heredar el inline del layout.invitaciones/metricas, app/(platform)/page.module.scss
Texto mínimoNada por debajo de 0.75rem (12px) en badges, hints o errores de validación.app-sidebar, tribe-switcher
La regla base no cambia: sin 100vh, sin 100vw fuera de overlays fullscreen, min-width: 0 en hijos flex/grid con texto y overflow-wrap: anywhere en nombres, emails y URLs.
03
Usage
// Control de formulario: 16px en mobile, compacto desde tablet.
.LessonComments__textarea {
  font-size: 1rem;

  @media (min-width: 48rem) {
    font-size: 0.875rem;
  }
}

// Tabla de gestión apilada en mobile.
@media (max-width: 47.99rem) {
  .PriceManagement {
    &__table,
    &__table > :where(thead, tbody) { display: block; }
    &__tableHeaderRow { display: none; }
    &__tableRow { display: grid; gap: 0.6rem; }
    &__tableRow > :where(td) { display: block; padding: 0; white-space: normal; }
  }
}

// Equivalente touch de un HoverCard.
const hasNoHoverPointer = useSyncExternalStore(subscribe, () => window.matchMedia("(hover: none)").matches, () => false);
return hasNoHoverPointer ? <Popover>…</Popover> : <HoverCard>…</HoverCard>;
04
Validation
  • Antes de cerrar un cambio de UI, capturar las rutas afectadas a 375×812 con Playwright (Chromium y WebKit, isMobile: true, hasTouch: true) y verificar que document.documentElement.scrollWidth no supere clientWidth.
  • Abrir los diálogos y overlays del flujo en ese viewport y confirmar que el footer con la acción principal queda visible o alcanzable por scroll interno.
  • Si un motor no puede ejercitarse en el entorno, dejar constancia del bloqueo concreto y de la validación más cercana realizada, como exige AGENTS.md.
05
Notes
  • Esta convención complementa Viewport Units y la regla "Cross-engine compatibility (Chromium and WebKit)" de AGENTS.md.
  • useIsMobile (hooks/use-mobile.ts) devuelve false en el servidor. Si un componente nuevo necesita elegir layout por viewport, seguir el patrón de doble render pre-hidratación descrito en la tabla en vez de confiar en el snapshot de servidor.
