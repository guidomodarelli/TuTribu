CONVENTION
Rich Text Links
Capa compartida para texto con links: autodetección de URLs, links markdown [texto](url) y un editor enriquecido reutilizable.
Scope: UI / Rich TextStatus: Active
01
Overview

La lógica de links de texto vive en una única capa compartida y se consume desde cualquier feature que necesite mostrar o editar contenido con enlaces. Hoy la usan el composer de mensajes (components/tribe-round) y la descripción de las lecciones de cursos.

El contenido se persiste como markdown crudo: links explícitos como [texto](url) y URLs sueltas como texto plano. Las URLs sueltas se convierten en enlaces clickeables solo al renderizar, no al guardar.

02

03
Rules
  • No dupliques la lógica de links: reutilizá lib/rich-text, RichTextContent y RichLinkEditor en lugar de reimplementar parseo o el editor.
  • Para mostrar contenido con links usá RichTextContent; pasá onLinkClick solo si necesitás interceptar el click (por ejemplo, frenar la propagación).
  • Para editar, creá el controller con useRichLinkEditor en el contenedor de la feature y pasáselo a RichLinkEditor. El controller expone serialize(), reset(markdown?), getDisplayState() y loadFromDisplay().
  • El copy del popover (Editar, Remover, Guardar, Cancelar, etc.) lo inyecta cada feature vía la prop copy, en español.
  • Cada feature define su propio límite de longitud como constante de módulo y lo valida en su use case. Mensajes: TRIBE_MESSAGE_CONTENT.maxLength (2000). Descripción de lección: COURSE_LESSON_DESCRIPTION.maxLength (2000).
RichTextContent renderiza un fragmento inline (sin wrapper) a propósito, para componer dentro de cualquier contenedor sin romper comportamientos sensibles al layout como -webkit-line-clamp en un ancestro.
04
Markdown soportado
  • Link explícito: [texto](https://...) renderiza un enlace con texto personalizado.
  • Autodetección: URLs sueltas (https://..., www...., dominios) se vuelven enlaces al renderizar. No se tocan las direcciones de email.
  • Autolink suprimido: [url](#) marca una URL detectada que el autor decidió dejar como texto plano.
  • Solo se aceptan protocolos http/https; cualquier otra cosa cae a texto plano.
05
Usage
// Mostrar contenido persistido con links.
import { RichTextContent } from "@/components/rich-text/rich-text-content";

<RichTextContent content={lesson.description} />

// Editar contenido con el editor enriquecido.
import { RichLinkEditor } from "@/components/rich-text/rich-link-editor";
import { useRichLinkEditor } from "@/components/rich-text/rich-link-editor/use-rich-link-editor";

const editor = useRichLinkEditor({ initialMarkdown: lesson.description });

<RichLinkEditor
  ariaLabel="Descripción"
  copy={DESCRIPTION_EDITOR_COPY}
  editor={editor}
  placeholder="Texto opcional debajo del video"
/>

// Al guardar: editor.serialize() devuelve el markdown a persistir.
06
Notes
  • La descripción de la lección se persiste como markdown crudo en la columna course_lessons.description (tipo text): el cambio de texto plano a markdown no requirió migración.
  • Las puras tienen tests en tests/unit/lib/rich-text; el renderer y el editor, en tests/unit/components/rich-text.
  • El editor controla el contentEditable a mano (no se actualiza su HTML vía React, solo se lee) y reaplica la selección con un useLayoutEffect; por eso el estado y los handlers viven en el hook y no en el componente de presentación.
