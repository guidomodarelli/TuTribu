CONVENTION
Repository Quality Gate
Validación automática en GitHub Actions y comprobaciones locales durante el desarrollo.
Scope: GitHub Actions / Vercel / agentsStatus: Active
01
Commits y pushes locales

El repositorio no ejecuta el gate desde hooks pre-commit ni pre-push. Los commits y pushes se envían sin esperar validaciones locales. El script prepare puede instalar los wrappers de Husky, pero no existe un hook de producto que invoque el gate.

Durante el trabajo, correr las comprobaciones relevantes al cambio: lint, type checks y las suites relacionadas. Los hooks Stop de agentes no deben duplicar el gate completo.

02
GitHub Actions: gate completo

.github/workflows/quality-gate.yml ejecuta pnpm run ci en cada push de una rama, incluidos los pushes a main, en las actualizaciones de pull requests y por ejecución manual. Los tags no activan este workflow. En pushes valida el commit enviado; en pull requests valida el commit de merge preparado por GitHub.

El runner instala Node.js según .nvmrc y pnpm según packageManager de package.json. Primero ejecuta pnpm install --frozen-lockfile, para rechazar diferencias entre el manifiesto y el lockfile. Después corre el contrato existente: lint, typecheck, typecheck:tests, toda la suite de Vitest y next build.

La caché de pnpm se identifica por pnpm-lock.yaml. Las ejecuciones obsoletas del mismo evento y ref se cancelan; cada job tiene un límite de 30 minutos. HUSKY=0 desactiva la instalación de hooks en CI y NEXT_TELEMETRY_DISABLED=1 desactiva la telemetría de Next.js.

El workflow usa contents: read, no conserva la credencial del checkout y no recibe secretos de la aplicación. Para recopilar las rutas durante el build, genera valores aleatorios efímeros para la configuración de Better Auth y Google, los enmascara en los logs y usa una URL de aplicación local y una URL PostgreSQL de loopback sin credenciales. Estos valores no habilitan login real ni conexiones a Neon. No ejecuta migraciones ni necesita las credenciales del proyecto Neon.

Un fallo de Actions no revierte el push. Para bloquear merges, configurar Quality gate como check obligatorio en la protección de la rama de destino. Agregar el workflow no modifica esa protección.

Los type checks del producto y del build usan tsconfig.typecheck.json. Los tests se chequean separadamente con tsconfig.test.json. Los outputs .next/, .open-next/ y los worktrees de .claude/ quedan fuera de los controles correspondientes.

pnpm run commitlint sigue siendo una comprobación independiente de los últimos 30 mensajes; no forma parte de pnpm run ci.

03
Vercel

Vercel sigue verificando el build real de deployment con el contrato nativo de Next.js y las variables sensibles del entorno. No reemplaza al gate completo: mientras vercel.json use ignoreCommand, un deploy salteado también saltea esa validación.

04
Validación esperada

Cuando cambie el workflow o el contrato ci, validar la sintaxis de Actions y ejecutar los comandos reales afectados. La ejecución remota se comprueba con una corrida de GitHub Actions después de publicar los cambios; no reemplazarla por tests que inspeccionen strings internos de archivos de configuración.

Cuando cambie commitlint.config.mjs o el script commitlint, validar mensajes observables del historial reciente y ejecutar pnpm run commitlint.
