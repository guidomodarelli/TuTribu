## Autorizaciones y recursos

- El usuario autorizó implementar la feature existente y publicar avances mediante commit y `push --no-verify`. El 2026-10-05 confirmó explícitamente que validó los 71 criterios de `checklists/admission-review.md` y pidió continuar. Los marcadores del archivo se conservan como artefacto del reviewer; esa validación humana no se usa para afirmar implementación ni aprobación de gates operativos.
- AGENTS y la constitución autorizan permanentemente crear, migrar, sembrar y eliminar ramas Neon efímeras propias de `cold-firefly-92947172`, incluido un rol temporal sin bypass cuando haga falta. Esta autorización no permite mutar la rama default/producción ni ejecutar allí `pnpm db:migrate`.
- El usuario renovó la sesión local Neon después de un `401`/`invalid_grant`; la comprobación posterior respondió `200` para el proyecto autorizado. No se registraron tokens, conexiones ni datos personales.
- Siguen pendientes la autorización de consumo Zavu por canal y destino, las credenciales y recursos de cada líder, la configuración de hosting/keyrings/época, el cliente Google preparado y un driver de producción. La implementación local debe mantener cerradas esas capacidades.

## Evidencia de preparación

Node `24.21.0`, pnpm `12.6.0` y `pnpm install --frozen-lockfile` verificados. Los siete casos del transporte pasaron: SDK real con rutas registradas, denegación sin red, pérdida de respuesta sin duplicar POST, cancelación, Google/JWKS real, scopes globales excluyentes y aborto previo sin efecto. Cuatro casos de fixtures verifican determinismo, aislamiento, estados comerciales/conducta, versiones y reloj independiente. Dos casos SQL reales, con `RUN_ADMISSION_SQL_TESTS=1`, verificaron roles, contexto, rollback y cleanup incluso ante un error falsy. Las ramas propias fueron eliminadas antes de terminar cada caso. Otro caso con transporte cerrado reprodujo creación incierta y reconciliación fallida: conserva ambas causas y el nombre de recurso, sin segundo POST ni callback SQL. La ejecución conjunta pasó 14 tests.

Pasaron `pnpm lint`, `pnpm typecheck` y `pnpm typecheck:tests`. La convención y los comandos están documentados en [admission-testing.htm](../../../docs/conventions/admission-testing.htm). Estos resultados completan la preparación T001–T006; no son evidencia de las migraciones ni de las capacidades del producto que aún no se implementaron. Se registrarán los ensayos posteriores con su alcance y resultados antes de cambiar el estado de un gate.
