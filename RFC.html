01
Contexto y objetivo

Cuando una persona paga la suscripción a Tribu, queremos mostrarle una página intermedia con tres botones que representan acciones relacionadas a sus cuentas de inversión. Elegir cualquiera de estas opciones le da acceso al grupo de WhatsApp privado con Marcos y su equipo.

El objetivo técnico es doble: mostrar ese modal al usuario y registrar internamente cuál botón eligió cada miembro, para que esa información aparezca en la sección "La tribu" del panel de administración y Vicky pueda hacer seguimiento a los que no eligieron nada.

Importante: No se requiere ninguna integración con APIs externas — ni IOL, ni IBKR, ni WhatsApp Business API. Todo el tracking es interno a la plataforma TuTribu. Los botones simplemente abren links (WhatsApp o URLs) y el click queda registrado en la base de datos propia.
02

Inmediatamente después de que Mercado Pago confirme el pago, antes de redirigir al usuario al feed de Tribu, mostrar un modal con las tres opciones.

04
Lógica de registro del click

Cuando el usuario hace click en cualquiera de los tres botones, antes de abrir el link o WhatsApp, hacer un fetch al backend para guardar la elección:

// Frontend — onClick de cada botón

async function registrarEleccion(userId, eleccion) {
  await fetch('/api/broker-eleccion', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      user_id:  userId,
      eleccion: eleccion,   // 'cambio_asesor_iol' | 'apertura_iol' | 'ibkr_fondos'
      fecha:    new Date().toISOString()
    })
  });
}

// Ejemplo de uso en el botón 1
boton_cambioAsesor.addEventListener('click', async () => {
  await registrarEleccion(userId, 'cambio_asesor_iol');
  window.open('https://wa.me/549XXXXXXXXXX?text=Hola+Marcos,+quiero+cambiar+mi+asesor+en+IOL');
});
// Backend — endpoint /api/broker-eleccion (Node/Express o lo que uses)

app.post('/api/broker-eleccion', async (req, res) => {
  const { user_id, eleccion, fecha } = req.body;

  await db.query(`
    UPDATE miembros
    SET broker_elegido = $1,
        broker_fecha   = $2
    WHERE id = $3
  `, [eleccion, fecha, user_id]);

  res.json({ ok: true });
});
Sin riesgo de pérdida de datos: el fetch se hace antes de abrir el link. Si el usuario cierra el tab igual, el registro ya quedó guardado.

Query para obtener los miembros con su elección:

-- Todos los miembros con su estado de broker
SELECT
  u.nombre,
  u.email,
  m.broker_elegido,
  m.broker_fecha,
  m.fecha_pago
FROM miembros m
JOIN usuarios u ON u.id = m.user_id
WHERE m.tribu_id = :tribu_id
ORDER BY m.broker_elegido = 'sin_elegir' DESC, -- sin elegir primero
         m.fecha_pago DESC;

-- Solo los que NO eligieron nada (para Vicky)
SELECT u.nombre, u.email, m.fecha_pago
FROM miembros m
JOIN usuarios u ON u.id = m.user_id
WHERE m.tribu_id = :tribu_id
  AND m.broker_elegido = 'sin_elegir'
  AND m.fecha_pago < NOW() - INTERVAL '24 hours'; -- más de 24hs sin elegir

09
🔴 Bug crítico — Error al volver de Mercado Pago
Prioridad máxima — resolver antes del lanzamiento. Este bug rompe la experiencia en el momento más crítico: justo después de que la persona pagó.

El problema: Cuando la persona completa el pago, Mercado Pago la mantiene dentro de su propio navegador o webview interno. Al intentar volver a la plataforma aparece un error y la persona no puede ver ni acceder a la asesoría. Resultado: acaba de pagar y no puede entrar.

El impacto: Genera desconfianza inmediata, la persona escribe preguntando si el pago se procesó, Vicky o Marcos pierden tiempo en soporte manual, y algunos pueden pedir devolución.

Soluciones posibles — elegir una o combinarlas:

Opción Cómo funciona Dificultad
A — URL de retorno (back_url) Configurar en Mercado Pago la back_url de éxito apuntando directamente a la página de acceso de la plataforma. Cuando el pago se confirma, MP redirige automáticamente a esa URL fuera de su webview. Fácil
B — Email automático post-pago Cuando MP confirma el pago vía webhook, la plataforma envía automáticamente un email al correo de la cuenta de MP con el link de acceso. La persona sale de MP, abre el mail y entra sin fricción. Funciona aunque el redirect falle. Media
C — Ambas combinadas ✅ Recomendado Redirect con back_url + email automático de bienvenida. Si el redirect falla, el email actúa como respaldo. El email también puede incluir el link de IOL y la invitación al grupo WA — se convierte en pieza de onboarding. Media
Recomendación: Opción C. El email de bienvenida automático no solo resuelve el bug — también es una oportunidad de onboarding. Puede incluir: link de acceso a la plataforma, link de apertura IOL, e invitación a elegir el broker para acceder al grupo WA privado.

Video en la plataforma — para empezar a postear
No hace falta construir un sistema de cursos completo para empezar. La necesidad inmediata es poder subir videos dentro de los posts de la asesoría — análisis, recomendaciones grabadas, comentarios de mercado. Hay dos formas de hacerlo sin construir nada complejo.

Opción A — Link embebido desde YouTube no listado (más simple, para arrancar ya)

Marcos sube el video a YouTube como no listado (no aparece en búsquedas ni en el canal). La plataforma embebe el reproductor de YouTube directo en el post. No hay costo de almacenamiento, no hay que construir nada de infraestructura, y el video se ve dentro de la plataforma sin que el usuario sepa que es de YouTube.

<!-- En el post de la plataforma — reproductor embebido -->

<div class="video-wrapper">
  <iframe
    src="https://www.youtube.com/embed/VIDEO_ID?rel=0&modestbranding=1"
    width="100%"
    height="400"
    frameborder="0"
    allowfullscreen
  ></iframe>
</div>

/* CSS — responsive */
.video-wrapper {
  position: relative;
  padding-bottom: 56.25%; /* 16:9 */
  height: 0;
  overflow: hidden;
}
.video-wrapper iframe {
  position: absolute;
  top: 0; left: 0;
  width: 100%; height: 100%;
}
Lo que necesita Guido: Agregar un campo "URL de video" opcional en el editor de posts. Si el campo tiene una URL de YouTube, renderizar el iframe embebido. Si está vacío, no mostrar nada. Son 2–3 horas de trabajo máximo.

Opción B — Videos alojados en Cloudflare Stream o Bunny.net (más profesional, para escalar)

Cuando la cantidad de videos crezca o se quiera mayor control, se puede migrar a un servicio de hosting de video dedicado. Las opciones más simples y baratas:

Servicio Precio Ventaja
Cloudflare Stream $5 USD/mes base + $1 por 1.000 minutos vistos Sin límite de almacenamiento, muy rápido, se embebe igual que YouTube
Bunny.net Stream $0.005 USD por minuto almacenado + ancho de banda Muy barato para bajo volumen, API simple, reproductor propio
YouTube no listado Gratis Sin infraestructura — para arrancar ya — la persona ve el reproductor de YT
Recomendación para arrancar: YouTube no listado + campo URL en el editor de posts. Costo cero, implementación rápida, permite empezar a postear videos esta semana. Migrar a Cloudflare Stream o Bunny cuando haya más de 20–30 videos o cuando se quiera quitar el branding de YouTube.
